# CONCORDE · Dossier projet
Passerelle de liaison comptable : migration Quadra → Odoo, et passerelle de données Odoo 17 (télécharger, analyser, envoyer, modifier). Détail technique dans `README.md`.

| Dossier | Contenu |
|---|---|
| `core/` | Moteur, en Python standard. Pipeline FEC (`fec_parser`, `mapping`, `lettrage`, `moteur`), contrôle dématérialisation (`demat`), **passerelle Odoo 17** : `odoo_source` (lecture SQL / XML-RPC), `telecharger` (FEC, xlsx, CSV), `analyser`, `xlsx_ecrire`. **Comptes et surveillance** : `comptes` (balance, grand livre, règles par compte), `surveillance` (changements, techniques, centre d'alertes), `journal` (CONCORDE raconte), `explications` (catalogue de Marceau). |
| `core/rapport_jour.py` | **Rapport du jour** : conclusions automatiques (sécurité, alertes, changements dans Odoo, travaux), modifiables (masquer, corriger, commenter, ajouter) ; choix gardés dans `/var/lib/concorde-interface/rapports/AAAA-MM-JJ.json` ; export en page imprimable. Écran « Rapport du jour ». |
| `core/comparaison.py` | **Comparer deux bases** sur une période (lecture seule) : vérification et analyse de chacune, puis totaux, soldes par compte / journal / tiers, écriture par écriture (rapprochement par numéro puis par contenu), analytique, conflits avec la date de copie. Écran « Comparer » et `scripts/concorde_comparer.py`. |
| `core/bases_locales.py` | Suppression / réinitialisation des bases Odoo **du serveur** après sauvegarde vérifiée pour une copie client, gardée 7 jours ; sans sauvegarde pour une base de test (ADR-0005). Clés API : révocation dans les bases du serveur, effacement des clés gardées par CONCORDE. Suppression chez un client : impossible par construction. Modèle vierge : `concorde_test_modele`. |
| `core/migration/` | **Migration ERP → Odoo** (ADR-0004), étapes 1 à 5 : `connecteur_fec` (lecture stricte), `filtres` (retrait d'écritures : journal, comptes, analytique, tiers, libellé, montants, période, conditions libres), `controles`, `correspondance` (table arbitrée, `a_arbitrer.xlsx`), `export` (FEC et CSV de contrôle, conformité au centime), `injection` (étape 6 : envoi dans `concorde_test` par l'API, lettrage vérifié, relecture au centime). Commande : `scripts/concorde_migrer.py` (`--tester`). |
| `securite/` | **Sécurité du serveur** (ADR-0007) : `concorde_securite.py controle` (mineur / rançongiciel, toutes les 15 min) et `antivirus` (ClamAV chaque nuit). Résultats dans `/var/lib/concorde-securite`, repris en alertes par l'interface. Signatures de la campagne du 01/11/2026 : `deploy/clamav/`. |
| `core/connecteurs/` | **Transferts entre logiciels** (ADR-0008) : `base` (ce que sait faire un connecteur : tester, lire, écrire, relire), `connexions` (annuaire `/var/lib/concorde-interface/connexions.json`, sans secret), `secrets` (`/etc/concorde/connecteurs/connecteurs.env`, dossier 700 et fichier 600, écriture atomique, ADR-0011), `transfert` (7 étapes par destination, feu vert, dossiers dans `/var/lib/concorde-interface/transferts/`), `fec` (FEC déposé ou produit), `odoo` (Odoo 17 par l'API ; `creer_manquants=oui` pour une base de test vierge), `azalplus` (source seulement : lecture seule de la base, ADR-0009), `pennylane` (API v2 ; jeton d'entreprise = bac à sable), `http_json` (client REST commun). Commande : `python3 -m scripts.concorde_connexion` (lister, ajouter, secret, tester, retirer). |
| `core/montee_version/` | **Montée de version Odoo** (ADR-0010, ADR-0012) : `photo` (photo comptable d'un Odoo 14 à 18, comparaison au centime), `openupgrade` (commits figés, table de couverture, `apriori.py` lus sans rien exécuter), `inventaire` (modules couverts, à vérifier, bloquants, saut par saut), `sauvegarde` (sauvegarde Odoo .zip : relire, extraire, produire), `montee` (conteneurs sur réseau interne, garde-fous disque et mémoire, sauts, feu vert, nouvel essai, livraison), `commandes` (seul lancement de programme, sans shell), `demandes` (file entre l'interface et le service de montée, effacement à 30 jours), `volume` (volume chiffré LUKS). Commandes : `scripts/concorde_montee.py`, service `scripts/concorde_montee_service.py` (root, `deploy/installer_montee.sh`). Vérifié par la CI : photo sur chaque version, montée 14 → 17 de bout en bout avec restauration de la base livrée dans Odoo 17 (`montee-pilotee`). |
| `injectors/` | Envoi vers Odoo par XML-RPC (`odoo17`, `odoo18`) et chaîne de conversion 14→19. |
| `interface/` | **Interface web** (ADR-0002, 0003, 0011, 0012) : Alertes, Comptes, Analyser, Télécharger, **Transferts**, **Montée de version** (`montees.py`), Journal, Historique, Bases ; surveillance automatique toutes les 15 min : `serveur.py` (Python standard), `auth.py`, `transferts.py` (écran Transferts : connexions, secrets saisis en masqué, dépôt de FEC, 7 étapes, feu vert), `static/` (HTML, CSS, JS). En ligne sur https://concorde.57-129-168-243.sslip.io, service `concorde-interface`. |
| `scripts/` | Commandes. `concorde_odoo.py` : `telecharger` et `analyser` (voir README). `concorde_interface_mdp.py` : changer le mot de passe de l'interface. |
| `tests/` | `python3 -m pytest` (464 tests, aucun sauté) ; contrôles qualité : voir `.github/workflows/qualite.yml`. |
| `deploy/` | Docker (Odoo 17 + PostgreSQL), modules Odoo 17 à 20, webhook de déploiement, service `concorde-interface.service`. |
| `docs/adr/` | Décisions d'architecture. ADR-0001 : passerelle de données Odoo 17. ADR-0002 : interface web. ADR-0003 : comptes, alertes, journal. ADR-0004 : migration ERP → Odoo. ADR-0005 : suppression de bases (local seulement). ADR-0006 : alignement prod sur test. ADR-0007 : sécurité du serveur. ADR-0008 : transferts entre logiciels (Sage, Cegid, Pennylane, AzalPlus, Odoo), un pivot et un connecteur par logiciel. ADR-0009 : AzalPlus lu dans sa base en lecture seule, écriture par l'API v2 une fois terminée. ADR-0010 : montée de version Odoo, OpenUpgrade non modifié lancé à part, comptabilité comparée au centime avant/après. |
| `samples/` | FEC synthétique de test. |

## Points ouverts
1. ~~Corriger l'injecteur~~ : fait le 06/11/2026 (`injectors/odoo17.py` et `odoo18.py` : euros et identifiants Odoo). L'envoi de la migration passe par `core/migration/injection.py`.
2. **Phase 3 — modifier** : corrections en masse et réintégration d'un xlsx modifié, avec remise en brouillon des écritures validées (ADR-0001).
3. **Tester la source XML-RPC sur un vrai Odoo** : il faut un login et une clé API sur l'instance du port 8017.
4. **Créer un rôle PostgreSQL en lecture seule** pour `--source sql`. Aujourd'hui, c'est l'utilisateur `odoo` qui sert.
5. **Base `concorde` en USD** (société « My Company ») : impossible d'en tirer un FEC. Passer la société en EUR, ou confirmer que cette base ne sert qu'aux essais.
6. **SIREN de la société Albhades absent dans `testalbhade`** : le FEC sort sous le nom `SIRENFEC…`. Le renseigner dans Odoo.
7. **`deploy/docker-compose.yml`** : modification non commitée qui retire les services Odoo 18, 19 et 20. À confirmer avant commit, car le webhook redéploie à chaque push sur `main`.
8. **Adresse du PostgreSQL** : l'interface joint le conteneur par son adresse Docker (172.18.0.2), qui peut changer quand le conteneur est recréé. Mieux : publier le port sur 127.0.0.1 dans `docker-compose.yml`.
9. **Brancher les écrans Envoyer et Modifier** de l'interface, une fois les phases 2 et 3 faites.
10. **Migration ERP → Odoo, étapes 7 et 8** (étape 6 faite le 06/11/2026) : test d'une écriture chez le client, envoi complet. Puis : écran « Migrer », connecteurs Excel/CSV à profils, AzalPlus (API), balance + tiers + plan, Sage et Quadra. Puis l'alignement prod sur test (ADR-0006).
11. **Filestore des bases supprimées** : il reste dans le volume Docker d'Odoo ; prévoir un nettoyage par root (`docker exec concorde-odoo rm -rf /var/lib/odoo/filestore/<base>`).
12. **Rôle PostgreSQL dédié** pour CONCORDE (lecture et suppression des seules bases Odoo), à la place du super-utilisateur `odoo`.
13. **Clés API de la base `concorde`** : trois clés admin à accès complet (`concorde`, `vibe`, `chatgpt`). À révoquer si elles ne servent plus (écran Bases > Clés API).
14. **`testalbhade` restaurée le 06/11/2026** depuis sa sauvegarde Concorde ; date de copie (14/10/2026 18 h 01 UTC) enregistrée dans `/var/lib/concorde-interface/bases_test.json`.
15. **Vitesse de l'étape 6** : environ 8 minutes pour 2 674 écritures (validation et lettrage un par un). À accélérer avant de traiter 45 000 écritures.
16. **Transferts entre logiciels (ADR-0008, ADR-0009, ADR-0011)** : socle `core/connecteurs/` et connecteurs **FEC**, **Odoo 17**, **AzalPlus (lecture)** et **Pennylane** faits (1.6.0) ; **écran Transferts** fait (ADR-0011) : connexions, secrets saisis en masqué dans l'écran, dépôt de FEC, 7 étapes, feu vert. Mise en place : `sudo install -d -o ubuntu -g ubuntu -m 700 /etc/concorde/connecteurs`, puis copie de `deploy/concorde-interface.service` et redémarrage. Reste, dans l'ordre : essais réels depuis l'écran — Odoo sur `concorde_test` (login + clé API), AzalPlus (réseau privé, rôle `concorde_ro` en lecture seule), Pennylane (jeton du bac à sable) : secrets saisis par Stéphane ; le fichier « comptes à arbitrer » rempli ne se redépose pas tel quel comme table (xlsx attendu au format « Numéro / Odoo Acct ») : à aligner ; **B** (API d'écriture dans l'AzalPlus en production, dépôt `MASITH-developpement/azalplus`) : reporté par Stéphane le 08/11/2026 ; Pennylane : règle des tiers (compte auxiliaire par tiers ?) et du lettrage, statuts lus, OAuth 2.0 pour la production ; puis Sage, Cegid, version xlsx des problèmes.
17. **Données AzalPlus à corriger** (mesuré le 08/11/2026) : 680 lignes d'écritures sans société, 2 lignes au statut « VALIDE » au lieu de « VALIDEE », tiers : sur 82 noms, 41 se résolvent en code, 28 désignent un client sans code, 13 sont introuvables (les lignes de ces 28 + 13 tiers sont bloquées à la lecture tant que ce n'est pas corrigé).
18. **Montée de version Odoo (ADR-0010, ADR-0012, acceptées le 08/11/2026)** : Odoo 14 à 18, sur le serveur CONCORDE avec garde-fous (ADR-0012), copies chiffrées supprimées à 30 jours, zéro écart, modules sur mesure hors périmètre. Fait : photo comptable, inventaire, montée conduite par la commande (`creer`, `circuit`, `feu-vert`, `nouvel-essai`, `livrer`), service de montée et volume chiffré, **écran Montée de version** (OpenUpgrade jamais nommé au client). Mise en place : `sudo bash /opt/concorde/deploy/installer_montee.sh` (clé du volume à sauvegarder hors du serveur). Reste : premier essai réel sur une base de test (arbitrage 5) ; mesurer la place disque d'une vraie base (9,4 Go libres : agrandir le disque si la base dépasse environ 2 Go décompressés) ; avant la première vente : avis d'un juriste sur l'AGPL d'OpenUpgrade et sur le fait de ne pas le nommer au client.
